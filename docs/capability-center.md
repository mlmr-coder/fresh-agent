# 能力中心

“能力中心”是智灵面向用户的统一能力入口，页面分为“专家”“技能”“连接器”三个标签。

每个会话当前选择的专家保存在用户数据目录 `~/.pinvou3/sessions/<会话 ID>/persona.json`，与应用安装目录分离。启动或打开历史会话时恢复绑定，并在恢复后的第一轮重新注入专家正文，随后仍使用轻量人设提醒；仅恢复挂件不能替代运行时恢复。`persona_events.json` 只用于展示历史，不参与判断当前是否挂载专家；没有当前绑定时，侧边栏只显示智灵图标。主动移除会保存显式空值；写入失败保留原选择并提示。会话删除时绑定随其私有目录清理。

- 专家：定义角色、专业背景、表达方式和工作偏好，由专家卡数据提供。
- 技能：只包含可独立使用的 `SKILL.md` 工作流程。
- 连接器：包含 MCP、外部 API、CLI 或授权流程；同时携带技能的组合包也只显示为一张连接器卡。

新增或合并上游能力时，应把后端市场条目放入已有的事实源：连接器进入 `list_marketplace_tools`，纯技能进入 `list_marketplace_skills`，专家进入专家卡数据。`companion_skills` 表示技能由连接器认领，界面会自动将组合包放到“连接器”并隐藏重复的技能卡。不要按名称、品牌或前端展示文案手工分组。

技能和连接器列表中的“按类型”读取技术形态标记，形成插件包、MCP、Skill、CLI、API 等分组；“按业务”读取条目的 `category` 元数据，形成沟通协作、文档知识、研发、金融、生活和其他等分组。这两个开关只改变浏览方式，不改变能力归属、安装状态或实际执行行为。

连接、安装、断开、卸载或更新完成后，详情页从刷新后的列表条目重新派生当前卡片。卡片、详情状态提示和顶部动作按钮必须使用同一份 `bundle_readiness`/市场状态，不能在详情弹窗中保留独立的连接状态。

聊天输入框按照“添加、工作模式、专家、连接器、知识库”的顺序展示，模型选择器位于右侧操作区。专家是单选能力，悬停后可从头像右上角取消。连接器显示最多三个已开启且授权状态可用的头像，超出使用 `+N` 表示；未完成授权的条目不会计入头像。连接器来源统一为 `BundleRegistry`：包含 MCP、CLI、组合包和带凭据的技能包（如 ima），通过 `bundle_readiness` 与 OAuth 状态判断可用性。点击头像组仍可逐项开关或进入能力中心添加。头像不代表会话级授权，开关仍沿用下文的模式级语义。

左侧普通会话列表使用智灵图标标识系统会话；会话绑定专家后，改为并列叠放智灵图标和专家头像。列表接口直接返回持久化的专家摘要，绑定、切换或卸下专家时立即刷新，因此未打开的历史会话和应用重启后的会话也能显示正确头像。

技能不在底部显示头像。在输入框任意位置键入 `/` 可按中文展示名称、内部名称、别名或描述选择已启用的技能；选择后在正文中显示“技能小图标＋中文名称”的浅灰标签，可连续添加多个，并在前后输入、整项删除、撤销；继续输入任务后发送。发送后的用户消息继续按能力中心的图标、颜色和中文名称显示技能标签，复制、编辑、持久化及提交给底座的内容仍是纯文本 `/技能名` 引用，不保存或发送 HTML。历史消息使用独立的展示目录识别技能标题、编码和别名；切换工作模式、停用或卸载技能只影响后续调用，不会把旧消息中的技能标签重新显示成普通 `/技能编码` 文本。技能列表来自 `list_composer_skills`：复用该模式的 `enabled_skills_for` 与 CodeWhale `SkillRegistry`，仅展示独立技能；使用 `BundleRegistry` 的包归属排除 CLI、MCP 组合包和凭据型连接器的配套技能。此筛选只影响选择列表，底座仍可按已启用连接器加载配套技能。底座已有的提示约定负责通过 `load_skill` 加载被用户点名的技能；选择技能不会增加工具权限，也不会更改全局开关。这里没有另建技能执行器，也不拦截或承诺模型一定按某条工作流程执行。

能力中心的技能卡直接读取 `list_composer_skills(scope: code)`，以蓝色“代码可用”或灰色“代码未启用”标识代码模式的真实状态；“代码可用”筛选只保留当前代码会话可调用的技能。点击“管理代码技能”可逐项开启或关闭代码模式权限，开启时同步解除该技能在代码模式下的隐藏状态。代码输入框的 `/` 面板使用同一事实源，并明确显示“代码可用技能”，因此能力中心、选择列表和实际注入代码会话的技能集保持一致。

`@` 列出当前会话的文件和附件，插入带完整路径的文件引用，避免同名文件混淆；选中建议不会自动发送。建议列表支持方向键、Enter/Tab 选择、Esc 关闭；输入法确认和 Shift+Enter 保持原行为。

从旧底栏技能开关升级时，启动迁移会一次性清理普通聊天中“已安装的独立技能”的遗留停用记录，解决技能中心显示已安装、`/` 却不可选的问题。迁移按包形态与归属判断，保留连接器、凭据型技能包、未安装包、隐藏设置及代码模式权限；完成标记保存在本机 `disabled_bundles.json`，后续启动不重复重置。选择列表与引擎继续共用迁移后的启用集，不能仅在前端补出不可执行的技能。安装、开关变化和窗口重新获得焦点会刷新技能建议。

后续合并上游新增技能时，保持实际 `SKILL.md`、别名和包归属元数据即可自动进入 `/` 列表，不要在前端硬编码技能名称；新增连接器继续登记能力包与对应就绪状态，不再维护一份输入框专用的 CLI 名单。普通聊天列宽统一为 850px，消息与输入框对齐；桌面侧栏默认展开，紧凑 Web 视口保持抽屉默认关闭。


输入框连接器菜单中的绿色开关、已连接标记、头像和数量统一由“连接就绪且未禁用”派生。就绪但禁用的连接器显示“已关闭”；未就绪的条目显示“待连接”和“去连接”入口，不显示绿色开关，也不计入头像。连接状态变化不改写用户保存的开关偏好。重新打开菜单、窗口获得焦点或收到能力变更事件时，统一刷新连接状态、模式开关与可见性；保存开关期间丢弃旧查询结果，刷新失败保留上次状态并提示。

连接器和技能开关按会话模式（普通聊天/代码）持久化，并约束该模式下的所有会话。当前轮次处理中会锁定开关；生成结束后可调整，工具禁用、技能目录和命令权限从下一轮起同步生效。

输入框默认保留 88px 的编辑高度，随内容增长至 200px 后内部滚动。上下文用量以模型名称前的小圆环表示，悬停、键盘聚焦或轻触可查看使用量、上限和百分比；接近上限时使用橙色/红色提示。正文与过程分层显示：思考和工具摘要使用紧凑灰色行，执行中的输出继续可见，完成后默认收起，失败和待确认信息保持可见。

## 删除连接器

上传的远程 MCP 与内置连接器使用同一授权入口。后端从 manifest 的 `servers` 中读取 OAuth 声明（`scopes`、`oauth` 或 `oauth_resource`），把服务名称提供给能力中心；只有实际授权成功才显示“已连接”。包已安装但未授权时显示“待授权／重新授权”，取消或失败后仍可重试。仅声明远程 URL 的公开或 API Key 服务不被当作 OAuth 服务。

连接器卡片和详情页的“更多”菜单提供“删除”：从当前应用移除连接配置、保存的授权信息及配套能力。已安装但未授权、授权过期或已关闭的连接器同样可以删除。CLI 连接器先退出登录并清理配套技能，再调用统一卸载入口；清理失败会提示错误并重新读取实际状态，不显示虚假的删除成功。上传的连接器包按现有机制进入回收站，外部账号和云端文件不受影响。预置目录中的可添加条目仍保留，便于重新连接。

## 删除技能

技能卡片和详情页使用与连接器一致的“更多”菜单。已安装的非内置技能可以从应用删除；未安装技能的删除入口禁用并说明原因，内置技能不能删除，只能按会话模式关闭。用户上传的独立技能先进入回收站，可恢复、导出或彻底删除；市场预置技能只删除本机安装副本，目录条目保留，之后可以重新安装。

删除独立技能会调用技能卸载入口；由连接器包提供的配套技能不能留下半个包，删除确认会明确说明并连同所属连接器及其他配套能力一起移除。卸载完成后后端重写所有在线会话的技能组合目录并刷新命令权限：正在执行中的轮次保持稳定，从下一轮消息起不再提供该技能。历史消息、已经生成的回答和产物不被删除。

## 会话过程展示

普通聊天、代码会话与子专家详情使用同一套过程展示，不改变底座消息结构。会话保持事件原始顺序：面向用户的进度说明与工具活动交错显示，回答保留在原位置。“正在工作 · 耗时”使用本轮开始时间，工具失败重试不重新计时；完成后显示“已工作”。折叠只隐藏思考和工具详情，不隐藏进度说明、提问或回答。长思考段落在局部区域滚动，默认追随新增内容，用户向上滚动时暂停追随。

进度说明来自模型实际输出的公开消息，与内部思考内容不同；前端不把内部思考转换为伪造的进度消息。

连接器列表采用统一卡片：48px 图标、名称、两行用途说明，底部固定显示连接状态与主操作。技术类型和密钥要求保留在详情中，列表不重复堆叠标签。每个连接器都有同位置的“更多”入口；未添加的条目禁用删除并说明原因，已添加的条目可删除，断开登录与删除应用配置分开处理。菜单支持键盘导航、Escape 关闭及焦点返回，窄屏自动改为单列。

连续工具调用在原位置合并为一条操作数量摘要，运行中显示进行数量，有错误时显示失败数量。默认不铺开完整命令；点击摘要后可逐项查看，列表最高 240px 并支持局部滚动。进度消息、提问和回答会中断工具分组，不能被跨越或挪动；实时会话与历史消息共用该规则。
