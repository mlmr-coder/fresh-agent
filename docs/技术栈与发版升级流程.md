## 0. 一页总览

```
┌─ 开发态 ────────────────────────────────────────────────────────┐
│  源码 GitHub (mlmr-coder/fresh-agent)                            │
│    └ 子模块 CodeWhale(底座 fork) + private-runtimes/windows(LFS) │
│  改 VERSION → push main                                          │
└───────────────────────┬─────────────────────────────────────────┘
                        ▼
┌─ 构建态 GitHub Actions (release-packages.yml) ───────────────────┐
│  gate: sync-version.mjs --check                                  │
│  4 个原生 runner 并行：                                            │
│    ubuntu-22.04      → linux-x64.deb                             │
│    ubuntu-22.04-arm  → linux-arm64.deb                           │
│    windows-latest    → windows-x64-setup.exe (NSIS)              │
│    macos-15          → macos-universal.dmg   (240 分钟超时)       │
│  publish: 算 SHA-256 → 生成 latest.json → gh release create      │
└───────────────────────┬─────────────────────────────────────────┘
                        ▼
┌─ 分发态 GitHub Release ──────────────────────────────────────────┐
│  v0.9.4/ 下：4 个安装包 + 4 个 .sha256 + latest.json              │
│  客户端硬编码拉取 releases/latest/download/latest.json             │
└───────────────────────┬─────────────────────────────────────────┘
                        ▼
┌─ 升级态 客户端自研 OTA（不是 Tauri updater）─────────────────────┐
│  启动即查 + 每 1 小时轮询 → 侧栏箭头 → 用户点击才下载安装          │

└─────────────────────────────────────────────────────────────────┘
```

**一句话**：构建、分发、更新三件事**全部**长在 GitHub 上，其中**分发与更新是硬绑定**（代码里写死 GitHub 域名，且正式版拒绝任何非 GitHub 的下载 URL）。

### 1.2 前端：刻意"瘦身"

源码是 **JSX + JSDoc**，不是 TS。`jsconfig.json:9` 开 `checkJs + strict + noEmit`，类型只做检查（`tsc -p jsconfig.json`）。

运行时依赖极简（只有 5 个）：

```
marked ^14.1.4        # Markdown 渲染
highlight.js ^11.11.1 # 代码高亮
dompurify ^3.4.14     # XSS 清洗
turndown ^7.2.4 + turndown-plugin-gfm  # HTML → Markdown
```

**无状态管理库**（zustand/redux/jotai 全无），自研 hooks 在 `src/hooks/`；**无 UI 组件库**。

Lint 矩阵异常重（9 套）：ESLint 10.9 + @eslint-react + react-hooks + unicorn + sonarjs + jsdoc + import-x + eslint-plugin-compat，另有 **oxlint / biome / knip（死代码）/ madge（循环依赖）/ jscpd（重复）**。

浏览器目标：Safari ≥ 14（`.browserslistrc:6-9`，Vite `target: 'safari14'`）。

> **技术栈含义**：前端几乎没有"生态包袱"，迁移成本极低——没有组件库私有依赖、没有付费 CDN。真正绑死的是 **Rust 侧 + GitHub 分发**（见 §4）。

### 1.3 Rust 侧

- crate 名 `pinvou3-tauri`，lib 名 `pinvou3_lib`，`default-run = pinvou3-tauri`；**不是 cargo workspace**。
- 主要插件：`log` / `dialog` / `notification` / `single-instance`（`Cargo.toml:68-71`）。**没有 `tauri-plugin-updater`**。
- 关键依赖：`tokio` 1.49(full)、`reqwest` 0.13(rustls)、`rusqlite` 0.39(bundled)、`zip` 8、`sha2` 0.11、`agent-client-protocol` 2（ACP 多 Agent）、`age` 0.12（加密）。
- Release profile：`lto = "thin"` + `codegen-units = 1` + `panic = "unwind"`（`Cargo.toml:404-439`）。
- **Clippy 是硬门禁**：`perf` / `dbg_macro` / `todo` / `wildcard_dependencies` 等 `deny`。

**一个必须知道的坑（rustc wrapper）**：

`.cargo/config.toml` 里**故意不设** `[build] rustc-wrapper`——因为它是全局键、无法按平台条件化，Windows 上指向无扩展名 sh 会报 **os error 193**。改为由构建入口注入 `RUSTC_WRAPPER` 环境变量（选择器 `src-tauri/scripts/rustc-stack-wrapper-select.sh:25-51`）。

原因：dev 下 O2 + 256 codegen-units 编译 `codewhale-tui` 时，LLVM 在 `MachineLateinstrsCleanup` 递归中**栈溢出（SIGBUS）**，需要 `RUST_MIN_STACK=16MiB`。release 构建同样会触发，所以 `release-packages.yml:444` 显式注入。**任何自建 CI 都必须复刻这一步**，否则 macOS 构建会在链接前崩掉。

### 1.4 底座 CodeWhale

`.gitmodules:1-3` → `mlmr-coder/CodeWhale`（上游 `Hmbown/CodeWhale`，"terminal coding agent, bring your own model"）。

- 20 个 crate 的 workspace：agent / app-server / core / tools / mcp / hooks / workflow / workflow-js(rquickjs) / lane / protocol / secrets / config / execpolicy / state / telemetry / tui 等。
- App 侧 4 个 path 依赖：`deepseek-tui`（即 `codewhale-tui`，用 `package=` 重命名保留本地别名）、`codewhale-secrets`、`codewhale-config`、`codewhale-execpolicy`。
- **已脱离上游**（`docs/fork-policy.md:1-9`，2026-09-10 决策）：不再整体同步，上游只读参考，取改动靠临时 `remote add upstream` + cherry-pick。基线 tag `pinvou-v0.9.5-r13-oauth1`。

> 提供能力：模型调用 / 流式输出 / 工具循环 / 会话 / Skills / Commands / MCP / Hooks / Compaction / Fleet。

### 1.6 平台依赖与产物形态

| 平台 | 产物 | 签名 | 关键约束 |
|---|---|---|---|
| macOS | **universal dmg**（aarch64 + x86_64 双 target） | **仅 ad-hoc**（`signingIdentity="-"`） | 无 Developer ID、无 notarization → 用户首次需 `xattr -dr com.apple.quarantine` |

## 2. 当前发版流程（完整链路）

### 2.1 版本单一事实来源

根目录 **`VERSION`** 文件（当前 `0.9.4`）。同步脚本 `scripts/sync-version.mjs` 覆盖 **9 个目标**（`:183-203`）：

```
src-tauri/tauri.conf.json · src-tauri/Cargo.toml
pinvou-knowledge/Cargo.toml · pinvou-knowledge/Cargo.lock
src-tauri/Cargo.lock（pinvou3-tauri + pinvou-knowledge 两项）
pinvou-cli/Cargo.lock（同两项）
pinvou3-app/package.json · package-lock.json（存在才纳入）
```

`--check` 不一致即返回 1（`:230-233`），作为 CI 门禁。

### 2.2 触发条件

```yaml
on:
  push:
    branches: [main]
    paths: ['VERSION']        # 只有 VERSION 变化才触发
  workflow_dispatch:          # 手动补打/重打
```

`concurrency.cancel-in-progress: false` —— 正式产物不可被中途取消。

### 2.3 六个 Job

| Job | Runner | 作用 |
|---|---|---|
| `check-version-bump` | ubuntu-latest | 跑 `sync-version.mjs --check` + `sync-version.test.mjs`，输出 `build_required` / `version` |
| `build-linux-x64` | ubuntu-22.04 | glibc 下限检查 → `--bundles deb` |
| `build-linux-arm64` | **ubuntu-22.04-arm** | 原生 ARM64 deb |
| `build-windows-x64` | **windows-latest** | 原生 NSIS exe |
| `build-macos-universal` | **macos-15** | 双 target + thin LTO，**timeout 240 分钟** |
| `publish-release` | ubuntu-latest | 汇总 artifacts → 生成 latest.json → `gh release create` |

macOS job 的注释记录了真实踩坑（`:430-435`）：冷缓存双 target + thin LTO，0.8.3 约 110 分钟，0.8.4 依赖面扩大后超 160 分钟，**150 分钟上限会在 pass2 链接阶段被杀**；release 缓存因 10GB LRU 上限基本不可能跨发布存活，**每次发布都按冷缓存规划**。

### 2.4 产物与清单

命名统一 `pinvou-agent_<version>-<platform>`（`generate-update-manifest.mjs:47`）：

```
pinvou-agent_0.9.4-linux-x64.deb
pinvou-agent_0.9.4-linux-arm64.deb
pinvou-agent_0.9.4-windows-x64-setup.exe
pinvou-agent_0.9.4-macos-universal.dmg
```

`latest.json` 由 `scripts/generate-update-manifest.mjs` 生成，平台 key **不是 Tauri 标准 target 名**（`:7-12`）：`linux-x64` / `linux-arm64` / `windows-x64` / `macos-universal`（macOS 不分架构）。

字段：`schema_version:1 / version / notes / pub_date / platforms{ version, url, format, sha256, size, restart_after_install }`。

**注意 `restart_after_install` 的平台差异**：Windows 为 `false`（NSIS 安装器自己接管），其余为 `true`。

### 2.5 发布动作

```bash
gh release create "v${VERSION}" release-assets/* \
  --target "$GITHUB_SHA" --title "Lingo ${TAG}" --generate-notes --latest
```

只用 `secrets.GITHUB_TOKEN`——**全仓 workflow 没有第二个 secret**（无签名证书、无 updater 私钥）。

## 3. 客户端升级机制（自研 OTA）

### 3.1 不是 Tauri updater

`tauri.conf.json`（全文 45 行）**没有 `updater` 段**；`Cargo.toml` 无 `tauri-plugin-updater`；`capabilities/` 无 updater 权限。

升级是**自研模块** `src-tauri/src/features/updater/`（7 文件，1107 行），前端 `src/platform/tauri/bridge/updater.js` + `src/features/updater/SidebarUpdateStatus.jsx`。

Tauri 命令（`app/commands/updater.rs:5-11`，用 macro 注册）：

```
get_app_version · check_for_update · download_update · install_update
restart_app · cancel_download · report_pending_update_result
```

### 3.2 检查策略

- 主窗口启动后**立即检查一次**；无更新则**每 1 小时**轮询（`updater.js:19` `UPDATE_CHECK_INTERVAL_MS`）。
- 发现新版本立即停止轮询，侧栏底部显示升级箭头。
- **自动检查失败全吞不打扰用户**；手动检查才显示错误（`manifest_missing` 归一，404 不暴露底层地址）。
- **下载与安装必须由用户点击触发**——无强制更新、无跳过版本、无 channel（stable/beta）。

### 3.3 三层 SHA-256 校验（无签名）

没有 minisign / Tauri 签名，改用 SHA-256：

1. **清单层**：`schema_version == 1`；`sha256` 必须 64 位 hex（`common.rs:330-337`）；`size` ∈ (0, 4GiB]（`:20,:118-123`）。
2. **下载层**：流式写 `.part` + 增量算 SHA-256，失败即删，原子 `rename`（`:272-283`）。
3. **安装前**：canonicalize 限定在 `paths::updates_dir()` 内、校验扩展名、**再算一次 SHA-256**（`:289-323`）。

### 3.4 安装与回滚

| 平台 | 行为 | 回滚 |
|---|---|---|
| Linux | `pkexec apt-get` 装 deb → 重启 | **无** |
| Windows | 静默启动已校验 NSIS → 退出旧进程 | **无** |
| macOS | 挂 dmg、校验 bundle id/版本/签名 → 替换 | **有**：备份为 `.fresh-assistant-update-backup`，失败 `rename` 回来（`platform/macos.rs:202-235`） |

另有：30 秒单 chunk 停滞看门狗（`mod.rs:23`）、旧下载清理（`common.rs:372`）。

## 4. 不依赖 GitHub 怎么做

### 4.1 先拆解：GitHub 在这套流程里承担了 6 个角色

| # | 角色 | 卡死程度 | 现状 |
|---|---|---|---|
| R1 | **源码托管**（git remote + submodule） | 低 | `mlmr-coder/fresh-agent`，2 个子模块 |
| R2 | **CI 算力**（原生 macOS/Windows/ARM runner） | **高** | macos-15 / windows-latest / ubuntu-22.04-arm |
| R3 | **制品存储与分发** | 中 | GitHub Release assets |
| R4 | **更新清单 host**（latest.json） | **高** | URL 写死在客户端二进制里 |
| R5 | **凭据** | 低 | 仅 `GITHUB_TOKEN` |
| R6 | **临时 artifacts**（90 天） | 低 | `actions/upload-artifact` |

**真正卡死的是 R4（客户端内置）和 R2（macOS 构建机）**，其余都能平移。

### 4.2 五个硬卡点（代码级）

#### ★ 卡点 1：更新清单 URL 写死在二进制里

```rust
// src-tauri/src/features/updater/platform/common.rs:16-19
const UPDATE_MANIFEST_URL: &str =
    "https://github.com/mlmr-coder/fresh-agent/releases/latest/download/latest.json";
const UPDATE_MANIFEST_ENV: &str = "PINVOU3_UPDATE_URL";
const GITHUB_RELEASE_PREFIX: &str = "https://github.com/mlmr-coder/fresh-agent/releases/download/";
```

#### ★ 卡点 2：正式版根本不读环境变量（最狠）

```rust
// common.rs:35-43
fn manifest_url() -> (String, bool) {
    #[cfg(debug_assertions)]          // ← 只有 debug 版才读 env
    if let Ok(value) = std::env::var(UPDATE_MANIFEST_ENV) { ... }
    (UPDATE_MANIFEST_URL.to_string(), false)
}
```

`docs/application-updates.md` 也明写："正式发布版会忽略该变量"。**已装到用户机器上的正式版，无论你怎么配环境、改 hosts、加配置文件，都只会去 GitHub 拉清单。**

#### ★ 卡点 3：非 GitHub 下载 URL 直接拒绝

```rust
// common.rs:339-352
fn validate_asset_url(value: &str, source_overridden: bool) -> Result<(), String> {
    if source_overridden { /* 只校验 http(s) 前缀 */ }
    if value.starts_with(GITHUB_RELEASE_PREFIX) { Ok(()) }
    else { Err("Update assets must come from the fresh-agent GitHub Release".to_string()) }
}
```

`source_overridden` 的取值来源是卡点 2 的 debug 分支 → **release build 里恒为 `false`**。

> **卡点 2 + 3 的组合后果**：你就算把 `latest.json` 和安装包全部搬到自己的服务器，**存量正式版客户端也会拒绝安装**，报错"必须来自 GitHub Release"。
>
> **因此：必须先发布一个"可配置更新源"的过渡版本，让用户升上来，才能切走。** 这是迁移的硬前置，不能跳过。

#### 卡点 4：清单生成器只认 `owner/repo`

```js
// scripts/generate-update-manifest.mjs:39,57
if (!/^[A-Za-z0-9_.-]+\/[A-Za-z0-9_.-]+$/u.test(repository)) { throw ... }
url: `https://github.com/${repository}/releases/download/${encodedTag}/${filename}`,
```

URL 是拼出来的，没有自定义 base URL 的开关。

#### 卡点 5：发布动作深度依赖 `gh` CLI

`release-packages.yml:625-634` 用 `gh release view/create/upload`，配合 `actions/upload-artifact` / `download-artifact`。

### 4.3 三档迁移方案

#### A 档 · 只换更新源（推荐起步，约 2-3 人日）

**保留** GitHub 托管源码与 CI，**只把制品与清单搬到自己的域名/对象存储**。

- 解决：下载速度、国内可达性、GitHub 账号被封时的升级命脉。
- 改动：
  1. `common.rs:16-19` → 常量改为从 tauri.conf.json 或编译期 env 注入的默认源（保留 GitHub 作为 fallback）。
  2. `common.rs:35-43` → 去掉 `#[cfg(debug_assertions)]`，改为正式版也读配置；加一个**允许的域名白名单**（而不是单一前缀）。
  3. `common.rs:339-352` → `validate_asset_url` 改为校验"白名单域名 + HTTPS"。
  4. `generate-update-manifest.mjs` → 加 `--base-url` 参数替代 `--repository`，不强拼 github.com。
  5. 发一个过渡版本（如 0.9.5）带新逻辑，等覆盖度上来再切清单地址。
- **必须先做的事**：把新逻辑的版本先发上去并观察升级覆盖率，否则存量用户会成为"孤岛版本"。

#### B 档 · 完全去 GitHub（约 2-4 周，含踩坑）

| 角色 | 替代方案 | 备注 |
|---|---|---|
| R1 源码 | **Gitea**（轻量，2G 内存可跑）/ GitLab CE / 腾讯云 CODING / 自建 git + SSH | 子模块 + LFS 需一并迁 |
| R2 CI | **Jenkins**（公司已在用）/ Gitea Actions / Drone / Woodpecker | **macOS 机器是硬门槛，见下** |
| R3 制品 | **腾讯云 COS / MinIO / S3** + CDN | 需保留 `latest.json` 与 `.sha256` |
| R4 清单 | 自建静态站 `https://download.yourdomain.com/latest.json` | 必须 HTTPS |
| R5 凭据 | 自建 secret store（Jenkins credentials / Vault） | 目前只有 GITHUB_TOKEN，压力小 |
| R6 artifacts | 制品库（Nexus / 对象存储） | — |

**macOS runner 是唯一无法绕开的硬门槛**：universal dmg 需要 macOS 上双 target 编译 + 链接（`rustup target add aarch64-apple-darwin x86_64-apple-darwin`），且**冷缓存约 160-240 分钟**。可选：

1. 一台 Mac Mini / Mac Studio 常驻（Jenkins agent 或 self-hosted runner）—— 最省事；
2. 云 macOS（MacStadium / AWS mac2 / GitHub 大 runner）—— 贵；
3. **降级方案**：放弃 universal，只出 aarch64（或分两个 dmg），工作量减半但仍需 macOS 机器。
4. ⚠️ **腾讯云轻量 2G 内存跑不了** —— 单是 Rust 依赖编译就需要 8G+ 内存，别考虑在这台机器上构建。

同理 Windows 原生 runner 也需一台 Windows 机器（MSVC + WebView2）。

#### C 档 · 混合（务实推荐）

- **源码 + CI 暂留 GitHub**（R1/R2 迁移成本最高、收益最低）；
- **制品 + 清单迁到自建 COS/CDN**（R3/R4）—— 这才是"命脉"，因为用户升级只依赖 R4；
- 同时按 A 档改造客户端，让更新源可配置（**这一步必须做**，否则 R4 迁不走）。

这样 GitHub 账号出问题时，你损失的只是 CI 与源码托管，**存量用户仍能正常升级**。

### 4.4 各角色的具体替换建议

**源码（R1）**

```bash
# Gitea 最轻，能跑在 2G 机器上
# 注意两件事：
#  1) 子模块 .gitmodules 的 URL 要一起改（CodeWhale + private-runtimes/windows）
#  2) private-runtimes 用 Git LFS，Gitea 需开 LFS 支持；
#     或直接改为对象存储直链（构建脚本下载 tarball），更省事
```

**CI（R2）** — 必须复刻的三件事：

1. `RUSTC_WRAPPER` 注入（`release-packages.yml:444`），否则 macOS 构建 SIGBUS；
2. 双 target 装到 **pinned toolchain**：必须在 `pinvou3-app/src-tauri` 目录下 `rustup target add`，否则 Tauri 切到 pinned toolchain 后找不到 x86_64 target（`release-packages.yml:452-460` 注释明确写了这个坑）；
3. `MACOSX_DEPLOYMENT_TARGET=11.0` + Node **24**。

**制品（R3）** — 目录结构建议与现状对齐，省得改脚本：

```
https://download.yourdomain.com/
  latest.json
  0.9.4/pinvou-agent_0.9.4-linux-x64.deb
  0.9.4/pinvou-agent_0.9.4-linux-x64.deb.sha256
  ...
```

**注意**：`latest.json` 必须 `Cache-Control: no-cache`（否则 CDN 缓存会导致用户看不到新版本）；安装包本身可以长缓存。

**更新源（R4）** — 客户端改造要点：

- 白名单化：`validate_asset_url` 从"单一前缀"改为"允许域名列表"，且**必须保留旧 GitHub 前缀**一段时间做兼容；
- 降级链：主源失败 → 备用源（GitHub）→ 提示，避免自建站挂掉时用户彻底升不了级；
- 保留 `PINVOU3_UPDATE_URL` 但改为正式版也生效（同时要有防滥用：只允许白名单域名，避免被劫持成任意 URL）。

### 4.5 顺带要补的债（迁移会放大它们）

| 债 | 现状 | 迁到自建域名后 |
|---|---|---|
| **macOS 无签名/公证** | ad-hoc，用户手动 `xattr` | Gatekeeper 拦截更严重，且非 GitHub 来源无社区信任背书 → **强烈建议补 Developer ID（$99/年）+ notarization** |
| **Windows 不签名** | NSIS 无签名 | SmartScreen 拦截率显著上升，企业环境基本装不上 |
| **无更新签名，只有 SHA-256** | 靠 HTTPS + GitHub 域名背书 | 自建域名背书弱 → 建议引入 **minisign** 或 Tauri 官方 updater 签名，把 `signature` 字段加进 `latest.json` |
| **Linux 只有 deb** | 无 rpm / AppImage | 若迁自建分发，顺手补 rpm 成本不高 |

## 5. 落地顺序与验收清单

```
第 0 步（前置，阻塞一切）
  └ 改造客户端更新源为可配置 + 域名白名单
     · common.rs:16-19 常量 → 可注入
     · common.rs:35-43 去掉 #[cfg(debug_assertions)]
     · common.rs:339-352 validate_asset_url → 白名单
     · generate-update-manifest.mjs 加 --base-url
  └ 发过渡版本 0.9.5，观察升级覆盖率 ≥ 目标阈值

第 1 步  搭制品分发（COS / MinIO + CDN + HTTPS 域名）
第 2 步  清单切到新域名（保留 GitHub 作为备用源）
第 3 步  源码迁 Gitea/GitLab（含子模块 + LFS 决策）
第 4 步  CI 迁 Jenkins/Gitea Actions（先迁 Linux，macOS/Windows 用实体机）
第 5 步  补签名（macOS Developer ID + notarization；更新清单 minisign）
```

**验收清单**

- [ ] 正式版客户端能读到自建域名的 `latest.json`（用正式 build 验，别用 debug）
- [ ] `validate_asset_url` 对自建 URL 放行，对随机域名拒绝
- [ ] 主源 404/超时 → 自动回落 GitHub 备用源
- [ ] `latest.json` 不被 CDN 缓存（`Cache-Control: no-cache`）
- [ ] 四个平台安装包 SHA-256 与清单一致，安装前二次校验通过
- [ ] macOS 回滚路径实测（故意让安装失败，确认能恢复旧版本）
- [ ] 自建 CI 能复刻 `RUSTC_WRAPPER` + 双 target，macOS 构建不 SIGBUS
- [ ] 从旧版本（0.9.4，内置 GitHub URL）能升到过渡版本
